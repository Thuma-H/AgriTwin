AgriTwin-ZM Cheat Sheet

This is a simple guide for presenting the project. It explains what the app does, what each file is for, and how to answer common questions without needing coding knowledge.

1) What this project does

AgriTwin-ZM is a Python project that helps show what may happen to farm products over time. It focuses on maize and tomato because they behave differently: maize stores longer, while tomatoes spoil faster.

  • It compares production with demand.
  • It shows if there is a surplus or a shortage.
  • It estimates loss, waste, and revenue.
  • It also gives simple policy warnings for food security.
Easy way to say it: “The project is a calculator for farm supply, demand, storage loss, and food security.”

3) What happens when the app runs

  1. The user opens the desktop app from main.py.
  2. The GUI appears with tabs like Run Simulation, Results, Dashboard, Policy, and Data & Export.
  3. The user enters values such as production, demand, price, and storage details.
  4. The code creates either a Maize or Tomato object.
  5. The simulation engine calculates the result.
  6. The dashboard saves the result and can export it.
Good demo line:
“The app takes simple farm numbers and turns them into easy-to-read results.”
Avoid saying:
“This is AI that predicts everything.” It is mostly rule-based simulation.

4) The simple logic behind maize

Maize is treated like a storage crop. The model keeps track of production, storage capacity, moisture level, price per ton, and monthly loss.

  • Maize.calculate_monthly_loss() = production × monthly loss rate.
  • The code checks that values are not negative.
  • Moisture level must stay between 0 and 100.
  • Maize revenue is based on tons sold × price per ton.
Simple explanation: maize loses a small amount each month while in storage.

5) The simple logic behind tomatoes

Tomatoes are treated as a fast-spoiling crop. The model stores shelf life, storage type, spoilage rate, and price per crate.

  • Tomato.calculate_spoilage(days_stored) reduces the remaining amount day by day.
  • Cold storage spoils slower than open storage.
  • The code uses a crate conversion of 15 kg per crate.
  • Revenue is calculated from crates sold × price per crate.
Simple explanation: tomatoes lose value quickly, so storage conditions matter a lot.

6) How the supply and demand engine works

The engine in engines/supply_demand.py is the main calculator. It compares what is produced with what is needed by the market.

  • Surplus: when production is higher than demand.
  • Shortage: when demand is higher than production.
  • Waste %: spoilage divided by production.
  • Food security %: how much of demand is met.
  • Price adjustment: price can go down or up if the market is unbalanced.
# simple explanation of the food security idea food_security = (demand_met / market_demand) * 100

7) Important numbers to remember

  • Food security label: above 80% = Secure, 60% to 80% = At Risk, below 60% = Crisis.
  • Maize price change rule: big surplus can reduce price by 15%; big shortage can raise price by 20%.
  • Policy reserve check: the default FRA threshold is 500,000 tons.
  • Storage rules: maize can be checked up to 180 days; tomato uses shelf life.
  • Tomato storage options: cold or open.
Remember: these are not random guesses. They are fixed rules written in Python.

8) What the dashboard does

The dashboard in reports/dashboard.py is like a simple results book. It stores every simulation result and can export the data in different formats.

  • It shows summaries for each month.
  • It gives the food security label.
  • It exports to TXT, CSV, and JSON.
  • It can load saved data back from simulation_data.json.

10) Do’s and don’ts for the presenter

Do:
  • Speak slowly and explain one tab at a time.
  • Use the words “production,” “demand,” “loss,” and “results.”
  • Show the sample data to prove the app already has example records.
  • Say that the project is written in Python.
  • Say the interface is made with Tkinter.
Don’t:
  • Do not call it machine learning.
  • Do not say it uses a big database or live government data if it does not.
  • Do not overcomplicate the explanation with technical terms.
  • Do not focus on code details unless asked.

11) Quick answers to common questions

Q: What language is the project written in?
A: Python.
Q: What is Tkinter?
A: A built-in Python tool for making windows, tabs, and buttons.
Q: Why are maize and tomato both included?
A: Because they behave differently. Maize stores longer, tomato spoils faster.
Q: What does “surplus” mean?
A: More product was made than the market needed.
Q: What does “shortage” mean?
A: The market needed more than was produced.
Q: How are results shown?
A: In the Results tab and through report exports.

12) More FAQ answers the examiner may ask

Q: Is the app online?
A: The main app is a desktop app. There is also a simple API mode in main.py.
Q: What is the API for?
A: It lets another app send JSON data to run maize or tomato simulations.
Q: What are the API endpoints?
A: GET /api/health, POST /api/simulate/maize, and POST /api/simulate/tomato.
Q: What is the role of the policy engine?
A: It checks simple food security rules such as reserve levels and storage limits.
Q: Does the app save data?
A: Yes. The dashboard can export results to TXT, CSV, and JSON.
Q: What does the sample JSON file do?
A: It contains example simulations already loaded into the project.
Q: How do tests help?
A: They confirm that the models, engines, and exports work as expected.
Q: Can I say the project is modular?
A: Yes. Each part is separated into files for models, engines, reports, and tests.
